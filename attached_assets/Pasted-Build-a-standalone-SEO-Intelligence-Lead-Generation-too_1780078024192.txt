Build a standalone SEO Intelligence & Lead Generation tool called “LaunchCore SEO Engine” that can integrate into an existing Laravel/Filament ecosystem.

This must not be only a frontend prototype. It must include the real application mechanics: backend API, database schema, crawler engine, job queue architecture, SEO diagnosis engine, todo generation engine, backlink opportunity engine, keyword research engine, lead generator, and integration layer.

Primary goal:
Create a standalone service that analyzes websites, generates complete SEO diagnostics, creates precise SEO todo lists, discovers lead opportunities, finds keyword opportunities, and identifies real backlink opportunities. The tool must be able to communicate with a Laravel/Filament app through secure API endpoints and/or iframe embedding.

Core architecture:
- Build as a standalone full-stack application.
- Include backend API endpoints.
- Include persistent database models.
- Include background job architecture for long-running tasks.
- Include crawler mechanics.
- Include integration-ready service classes for external APIs.
- Include a minimal internal UI only if needed to test the workflows.
- The Laravel/Filament ecosystem will remain the main system of record, but this tool should be able to run independently and sync data through APIs/webhooks.

Preferred stack:
- Use a robust backend framework suitable for Replit.
- Use PostgreSQL or SQLite for development with a clear path to PostgreSQL production.
- Use background jobs or a queue abstraction.
- Use TypeScript if using Node.js.
- If a frontend is included, keep it secondary and focused on testing the backend workflows.

The tool must include these modules:

1. Site crawler
Create a crawler that accepts a root URL and crawls internal pages.

Required crawler features:
- Normalize domains and URLs.
- Handle URLs without protocol.
- Respect crawl limits.
- Avoid duplicate URLs.
- Stay within the same domain unless configured otherwise.
- Fetch HTTP status codes.
- Detect redirects.
- Extract page title.
- Extract meta description.
- Extract H1 and H2 headings.
- Extract canonical URL.
- Extract robots meta tags.
- Extract internal links.
- Extract external links.
- Extract image URLs and alt attributes.
- Detect forms.
- Detect phone links.
- Detect email links.
- Detect CTA-like buttons/links.
- Detect analytics/tracking snippets.
- Calculate word count.
- Save crawled pages to database.
- Save crawl status: pending, running, completed, failed.
- Save crawl errors.

2. SEO diagnosis engine
After a crawl, generate structured SEO issues.

Detect at minimum:
- Missing title.
- Title too short.
- Title too long.
- Duplicate titles.
- Missing meta description.
- Meta description too short.
- Meta description too long.
- Duplicate meta descriptions.
- Missing H1.
- Multiple H1s.
- Missing canonical.
- Broken internal links.
- Broken external links if feasible.
- 4xx pages.
- 5xx pages.
- Redirect chains if feasible.
- Images missing alt text.
- Thin content pages.
- Non-indexable pages.
- Missing Open Graph tags.
- Missing schema markup.
- Missing LocalBusiness schema for local businesses.
- Pages too deep in crawl structure.
- Missing contact signals.
- Missing conversion CTA.
- Missing tracking scripts.

Each issue must have:
- issue_type
- category
- severity: critical, high, medium, low
- affected_url
- evidence
- recommendation
- business_impact
- estimated_effort
- confidence_score

3. SEO todo generation engine
Generate a precise todo list from the SEO issues.

Each todo must contain:
- title
- description
- target_url
- priority: P1, P2, P3, P4
- category
- exact_action
- why_it_matters
- expected_impact
- estimated_time_minutes
- implementation_notes
- validation_method
- status: new, planned, in_progress, implemented, validated, ignored

Examples:
- “Rewrite the title tag on /services/plumbing to include the primary service and city.”
- “Add a clickable phone CTA above the fold on mobile.”
- “Create a dedicated location page for emergency plumbing in Laval.”
- “Add LocalBusiness schema to the homepage.”
- “Compress hero image on homepage because it is likely hurting mobile speed.”
- “Add internal links from the homepage to the three most important service pages.”

17. Product philosophy
This tool is part of the LaunchCore ecosystem. It should not only show SEO data. It must convert SEO data into precise business actions.

The key output is:
- What is wrong?
- Why does it matter?
- What exact action should be taken?
- How much impact can it have?
- How hard is it?
- How do we validate that it was fixed?
- What backlink opportunities can improve authority?
- What keyword opportunities can drive leads?
- What should the business do this week?

Build this as a real mechanics-first tool that can later be embedded in a Laravel/Filament dashboard through iframe or connected directly by API.
